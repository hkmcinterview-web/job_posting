# 텔레그램 → 네이버카페 자동 게시 봇 (+ 카드뉴스 생성)

내 텔레그램 봇에게 메시지 맨 앞에 **키워드**를 붙여서 보내면 동작이 갈립니다:

- **`카페`** 로 시작 → 그 아래 내용을 편집한 그대로 **네이버카페에 글 게시**
- **`카드`** 로 시작 → 링크마다 AI가 **헤드라인 후보를 2~3개 제안** → 텔레그램에서 숫자로 답장하면 그걸로 **카드뉴스 1장**을 만들어 회신

```
"카페 ..." ──► 제목/본문 분리 ──► 카페 글 편집(editor.py) ──► 네이버카페 게시

"카드 링크1 링크2" ──► 링크마다: 기사 수집 ──► 헤드라인 후보 2~3개 생성(Gemini/Claude)
                                              │
                        텔레그램에 후보 전송 ◄─┘
                                │
                        사용자가 숫자로 답장
                                │
                        그 후보로 카드뉴스 1장 렌더링 ──► 텔레그램 회신 ──► 다음 링크로
```

## 1. 설치

24시간 켜져 있는 서버/PC(라즈베리파이, 클라우드 VM 등)에서:

```bash
cd telegram_naver_bot
pip install -r requirements.txt
cp .env.example .env   # 열어서 값 채우기
```

## 2. 텔레그램 봇 준비

1. 텔레그램에서 **@BotFather** 검색 → `/newbot` 으로 봇 생성 → 토큰 복사
2. `.env` 의 `TELEGRAM_BOT_TOKEN` 에 입력
3. `python main.py` 실행 후 봇에게 아무 메시지나 보내면 콘솔에 `chat_id` 가 출력됩니다
   → 그 값을 `TELEGRAM_ALLOWED_CHAT_IDS` 에 입력 (다른 사람이 봇을 악용하지 못하게 필수!)

## 3. 네이버 API 준비 (카페 게시용)

> 네이버 아이디/비밀번호를 저장하지 않고 **공식 카페 API + OAuth** 를 사용합니다.
> 자동화 로그인(셀레늄 등)은 캡차·약관 문제로 권장하지 않습니다.

1. [developers.naver.com](https://developers.naver.com/apps/#/register) → 애플리케이션 등록
   - **사용 API**: "네이버 로그인" + "카페" 선택 (카페 API 는 권한 신청이 필요할 수 있음)
   - **Callback URL**: `https://localhost/callback` (또는 `.env` 의 `NAVER_REDIRECT_URI` 와 동일하게)
2. 발급받은 Client ID / Secret 을 `.env` 에 입력
3. **카페 ID(clubid)** 찾기: 카페 관리 페이지 URL 이나 카페 글 URL 의
   `cafe.naver.com/ca-fe/cafes/12345678/...` 형태에서 숫자,
   **게시판 ID(menuid)** 는 게시판 URL 의 `menuid=` 뒤 숫자입니다 → `.env` 에 입력
4. 최초 1회 로그인:

```bash
python naver_auth.py
```

출력된 URL 을 브라우저에서 열어 로그인/동의 → 이동된 주소를 붙여넣으면
`naver_tokens.json` 이 생성됩니다. 이후에는 봇이 토큰을 자동 갱신합니다.

> ⚠️ 글을 쓰려는 계정이 해당 카페의 **멤버이고 그 게시판에 쓰기 권한**이 있어야 합니다.

## 4. (선택) AI 요약 — 카드 헤드라인 품질 향상

카드뉴스 헤드라인을 위트있게 만들어줄 AI 키를 넣으세요 (둘 다 없으면 기사 제목을
그대로 쓰는 방식으로 자동 대체되고, 이 경우 후보 선택 없이 바로 카드가 만들어집니다).

- **구글 Gemini (무료 등급, 추천)**: [aistudio.google.com/apikey](https://aistudio.google.com/apikey) 에서
  발급 → `.env` 의 `GEMINI_API_KEY` 에 입력
- **Claude (유료)**: `ANTHROPIC_API_KEY` 에 입력 (Gemini 키가 있으면 Gemini 를 우선 사용)

키 하나만 있으면 됩니다. Gemini 키 테스트는 `python test_gemini.py` 로 바로 확인할 수 있어요.

## 5. 실행

```bash
python main.py
```

상시 실행하려면 (Linux):

```bash
nohup python main.py >> bot.log 2>&1 &
```

## 6. 사용법

### 📝 카페에 글 올리기 — `카페`

```
카페
제목: 7월 첫째주 자동차산업 뉴스
이번 주 주요 뉴스를 정리했습니다.

현대차 하반기 채용 확대
https://n.news.naver.com/article/...
```

- 올리기 싫은 뉴스는 **직접 지운 뒤** 보내면, 남긴 내용 그대로 카페에 올라갑니다
- 첫 줄 `제목:` → 카페 글 제목 (없으면 첫 줄이 50자 이하일 때 제목으로 사용,
  둘 다 아니면 `[날짜] 뉴스 브리핑` 자동 생성)
- 본문 속 링크는 쓴 위치 그대로 클릭 가능한 링크로 유지됩니다
- 카드뉴스는 만들지 않습니다 (텍스트 글만)

### 🖼 카드뉴스 만들기 — `카드`

```
카드
https://n.news.naver.com/article/1
https://n.news.naver.com/article/2
```

- 링크는 최대 `MAX_LINKS`(기본 5)개까지 처리
- **링크마다 순서대로** 처리됩니다:
  1. 봇이 헤드라인 후보 2~3개를 번호와 함께 보여줌
  2. `1`, `2`, `3` 중 숫자로 답장
  3. 그 후보로 **카드뉴스 1장**을 만들어 회신
  4. 곧이어 **기사 요약 + 출처 링크**를 별도 메시지로 보내드립니다
     (인스타그램 등에 카드뉴스 올릴 때 캡션으로 바로 복사해서 쓰면 됩니다)
  5. 다음 링크로 자동 진행 (모든 링크 끝나면 완료 메시지)
- AI 키가 없거나 요약에 실패하면, 후보가 1개(제목 기반)뿐이라 **묻지 않고 바로** 카드가 만들어집니다
  (이 경우 요약문은 기사의 og:description 이나 본문 앞부분으로 대체됩니다)
- 선택을 기다리는 도중 숫자가 아닌 메시지(`카페 ...` 등)를 보내면, 대기 중이던 선택은 취소되고 새 메시지가 정상 처리됩니다
- 봇을 재시작하면 선택 대기 상태는 초기화됩니다 (그 링크부터 `카드`로 다시 시작하면 됨)
- 카페에는 자동으로 올라가지 않습니다 (카드 이미지 + 요약 텍스트만 텔레그램으로 회신)

## 파일 구성

| 파일 | 역할 |
|---|---|
| `main.py` | 메인 루프 (텔레그램 수신 → 카페/카드 라우팅 → 후보 선택 상태 관리) |
| `message_parser.py` | 키워드(`카페`/`카드`) 판별, 제목/본문/링크 분리 규칙 |
| `editor.py` | 카페 글 편집 규칙 (머리말/꼬리말, 링크 유지) — **편집 규칙 수정은 여기** |
| `article.py` | 뉴스 기사 수집 (본문, 대표사진 후보, 언론사명) |
| `summarize.py` | 카드 헤드라인 후보 생성 (Gemini/Claude/휴리스틱) |
| `card_news.py` | 카드뉴스 PNG 렌더링 (1080×1350) — **디자인 수정은 여기** |
| `naver_cafe.py` | 카페 글쓰기 API + 토큰 자동 갱신 |
| `naver_auth.py` | 최초 1회 네이버 OAuth 로그인 |
| `test_gemini.py` | Gemini API 키 단독 테스트 도구 |

## 알아둘 점

- 한글 폰트(Noto Sans CJK KR, 주아체)는 최초 실행 시 `fonts/` 에 자동 다운로드됩니다.
- `naver_tokens.json`, `.env` 에는 민감 정보가 있으니 절대 커밋하지 마세요 (`.gitignore` 처리됨).
- 네이버 refresh_token 도 장기간 미사용 시 만료될 수 있습니다 — 게시 실패 시 `python naver_auth.py` 재실행.
- 카드 후보 선택 대기 상태는 메모리에만 있어 **봇 재시작 시 사라집니다** — 여러 사용자가 동시에 서로 다른 링크의 선택을 진행해도 chat_id 별로 분리되어 섞이지 않습니다.
